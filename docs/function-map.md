# Карта функций

Что за функция — как должна работать — как проверить. Одна строка на единицу.

Колонка **✓** заполняется при прогоне: ✅ проверено, ❌ сломано, · не проверялось.
Дата последнего прогона: **2026-09-11**. Прогнано всё, что можно запустить без
телефона и без реального платежа — 16 команд из 17, все роуты витрины, авторизация.
Не прогнан только `python -m pi bot`: он требует живого Telegram.

> Подписка сейчас **выключена** переключателем `PI_SUBSCRIPTION` — полка
> открыта всем. Денежные строки описывают включённое состояние.
> См. `docs/subscription.md`.
Автотесты: 710 зелёных, `ruff` чист.

Осталось на человека всё, где нужно нажимать в Telegram или платить звёздами, —
см. «Что может прогнать только владелец» в конце.

## CLI — `pi <команда>` (17 подкоманд, `pi/cli.py`)

| ✓ | Команда | Как должна работать | Как проверить |
|---|---|---|---|
| ✅ | `python -m pi sites` | Читает `data/sites.txt` в таблицу магазинов, схлопывая `www.` (`pi/domains.py`) | `python -m pi sites`, затем `SELECT COUNT(*) FROM stores` — растёт, дублей по домену нет |
| ✅ | `python -m pi detect` | Пробует магазин на Shopify / JSON-LD / ASOS, запоминает способ чтения | `python -m pi detect --limit 5 --only <домен>`, проверить `stores.platform` |
| ✅ | `python -m pi run` | Полный прогон: сбор → классификация → оценка → уведомления | `python -m pi run --dry-run --stores <домен>` печатает сообщения, ничего не шлёт |
| · | `python -m pi run --collect-only` | Только собрать цены, не оценивать | `COUNT(*) FROM price_points` до и после |
| · | `python -m pi run --rescan` | Оценить все варианты в наличии, а не только изменившиеся | `--dry-run`, кандидатов заметно больше |
| ✅ | `python -m pi verify` | Открыть самые старые карточки поштучно, мёртвые снять с полки | `python -m pi verify --limit 20 --dry-run` → «проверено N · снято M» |
| ✅ | `python -m pi seed` | Пометить всё подходящее сейчас как уже виденное | `python -m pi seed --dry-run` печатает число; `alerts` не растёт |
| ✅ | `python -m pi prune` | Удалить старую историю цен и товары, пропавшие из каталога | размер `data/pi.db` падает, свежая цена каждого варианта на месте |
| ✅ | `python -m pi backup` | Согласованная копия базы | `python -m pi backup --out /tmp/x.db`, затем `PRAGMA integrity_check` |
| ✅ | `python -m pi grant` | Выдать или забрать доступ без оплаты | `python -m pi grant <id> --days 7` — полка открывается; `--revoke` закрывает |
| ✅ | `python -m pi subscriptions` | Напомнить перед концом, закрыть просроченные, вернуть Stars | `--dry-run` перечисляет; `--refund` возвращает и снимает доступ |
| ✅ | `python -m pi digest` | Две лучшие находки дня бесплатным читателям | `python -m pi digest --count 2 --dry-run` печатает две |
| ✅ | `python -m pi reindex` | Пересобрать артикулы, по которым товары сшиваются между магазинами | `COUNT(*) FROM product_keys`; `python -m pi price <артикул>` находит соседей |
| ✅ | `python -m pi reclassify` | Пересчитать бренд, пол, тип и аудиторию по всему каталогу | доля `audience IS NULL` падает; **необратимо — сначала `python -m pi backup`** |
| ✅ | `python -m pi find` | Поиск по текущим скидкам с фильтрами | `python -m pi find --brand nike --size EU44` печатает строки |
| ✅ | `python -m pi price` | Что каждый магазин просит за артикул или название | `python -m pi price CW2288-111` — несколько магазинов по возрастанию цены |
| · | `python -m pi bot` | Держать телеграм-бота | запустить, `/start` в боте отвечает |
| ✅ | `python -m pi web` | Отдавать витрину | `python -m pi web --owner <id>`, открыть `http://127.0.0.1:8000/` |
| ✅ | `python -m pi health` | Сводка здоровья сбора | `python -m pi health` печатает сводку |

## Известные ограничения

- **Прокрутка через границу прогона.** `record_offers` переписывает строки тех вариантов, чья цена изменилась (`pi/db.py:494-497`), поэтому листание в момент прогона может показать карточку дважды. Сортировка тут ни при чём — у всех шести режимов есть уникальный тай-брейкер.
- **ASOS не перепроверяется поштучно.** `VERIFIABLE = ("shopify", "jsonld")` (`pi/pipeline.py:277`): у адаптера ASOS нет страницы отдельного товара. Сейчас это 12 предложений из 33 208.
- **Одинаковая вещь в разных магазинах — разные карточки.** Схлопываются только размеры одного товара и только при равной цене. Между магазинами — 3 508 повторов, требуют отдельной работы по сшиванию артикулов.
- **Разметка пола и аудитории устаревает.** Правила улучшались, а старые строки остались с прежними значениями. Лечится `python -m pi reclassify` — операция необратимая, перед ней `python -m pi backup`.

## Что нашёл прогон

- **`python -m pi find` не знал про границу магазина.** На запрос «Nike, EU44» выдавал четыре
  женские вещи подряд, хотя на витрине и в боте их уже не было. Починено: теперь
  фильтрует, а `--women` открывает их владельцу для проверки классификации.
- **Дайджест шлёт неделю назад проверенную цену.** Лучшая находка дня в бесплатной
  рассылке помечена «проверено 7 дн назад». Это витрина продукта для тех, кто ещё не
  платит, и она показывает цену, за которую никто не ручается.
- **В дайджесте пустые размеры** — «Есть: —». Либо у товара нет записей о наличии,
  либо `sizes_in_stock` не находит их по последней точке цены. Не разбиралось.
- **Детское НЕ просачивается — проверено.** Ранее в этом файле стояло обратное.
  Запрос по видимой полке даёт ноль: `Big Kid's`, `Grade School`, `Niño` и
  категории `kids/*` уже помечены и уже скрыты. Прежний вывод был сделан по
  выборке товаров без *пола*, а не по тому, что реально видно.
- **Разметка не устарела.** `python -m pi reclassify` на копии базы дал 160 010
  товаров с полом против 160 605 бывших и 27 186 детских против 27 185 — то есть
  ничего. Запускать её ради обновления смысла нет.
- **Авторизация витрины держится.** Без подписи `/api/favorites` → 401, полка → 402,
  подделанная подпись → 401, запись чужому id → 401. Проверено запросами.
- **`prune` принимает `--keep-days`, а не `--days`.** Мелочь, но искал не там.
- **Пол по коду модели не читается.** `W Air Max Craze`, `PUMA MAYZE WNS`,
  `NB WRPD` — женские модели, у которых пол не проставлен, потому что правило смотрит
  только на слова, а не на суффиксы моделей.

## Что может прогнать только владелец

Всё ниже требует телефона с Telegram, а часть — настоящего платежа звёздами.
Порядок важен: сначала деньги, потом остальное.

**1. Деньги (30 минут).**
```
python -m pi bot                      # в одном терминале
python -m pi web --owner <ваш id>     # в другом, если проверяете витрину локально
```
- `/start` → приходит приветствие, в `bot_users` появилась строка.
- `/subscription` → состояние совпадает с `python -m pi subscriptions --dry-run`.
- Кнопка покупки → счёт в звёздах открывается. **Оплатить с тестового аккаунта.**
- После оплаты: полка открывается, `python -m pi subscriptions --dry-run` видит подписку.
- `/cancel` → автопродление снято, доступ до конца оплаченного.
- `python -m pi subscriptions --refund <id>` → звёзды вернулись, доступ закрыт.
- `/admin` из **группы** → «не понял». Из личного чата → панель. С чужого аккаунта → «не понял».

**2. Полка внутри Telegram (15 минут).**
- Кнопка витрины в боте открывает Mini App, и он **не** показывает предложение подписаться.
- С аккаунта без подписки — наоборот: предложение, и кнопка в нём возвращает в бота.
- Прокрутить полку до конца: одна и та же вещь не должна встретиться дважды.
- Открыть карточку: видны другие магазины, лучшая цена, размеры.
- Поставить и снять сердечко, открыть «Избранное».
- Проверить на экране 390 px: нет горизонтальной прокрутки, картинки грузятся,
  названия не обрезаны на полуслове.

**3. Сбор (можно оставить на ночь).**
```
python -m pi detect --limit 5 --only <домен>
python -m pi run --dry-run --stores <домен>
python -m pi verify --limit 20 --dry-run
python -m pi backup --out /tmp/x.db && sqlite3 /tmp/x.db "PRAGMA integrity_check"
```

**4. Разметка — необратимо, сначала копия.**
```
python -m pi backup --out data/before-reclassify.db
python -m pi reclassify
```
После этого перемерить: `SELECT gender, COUNT(*) FROM products GROUP BY 1`.
